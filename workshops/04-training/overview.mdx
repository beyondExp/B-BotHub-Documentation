## Types of Training

B-Bot offers multiple training approaches:

```
┌────────────────────────────────────────────────────────────────┐
│                    TRAINING METHODS                            │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐      │
│   │   Document   │   │     QA       │   │    Fine-     │      │
│   │   Retrieval  │   │    Pairs     │   │   Tuning     │      │
│   │   (RAG)      │   │              │   │              │      │
│   └──────────────┘   └──────────────┘   └──────────────┘      │
│         │                  │                  │               │
│         ▼                  ▼                  ▼               │
│   Add searchable     Exact Q&A          Train custom         │
│   knowledge base     matching           model weights        │
│                                                                │
└────────────────────────────────────────────────────────────────┘
```

<CardGroup cols={3}>
  <Card title="Document Retrieval (RAG)" icon="file-lines">

## Document Training (RAG)

### How RAG Works

```
User Question: "What's the warranty on SmartHub?"
           │
           ▼
   ┌─────────────────┐
   │ Vector Search   │ ──► Finds relevant chunks
   │ in Documents    │     from your uploaded docs
   └─────────────────┘
           │
           ▼
   ┌─────────────────┐
   │  LLM Generates  │ ──► Creates answer using
   │  Response       │     retrieved context
   └─────────────────┘
           │
           ▼
"The SmartHub has a 2-year warranty covering..."
```

### Uploading Documents

1. Navigate to **Training** in the sidebar
2. Click **Documents** tab
3. Click **Upload Documents**

### Supported Formats

| Format | Best For | Notes |
|--------|----------|-------|
| **PDF** | Manuals, reports | Extracts text and structure |
| **DOCX** | Word documents | Preserves formatting |
| **TXT** | Plain text | Simplest format |
| **MD** | Markdown docs | Great for technical docs |
| **CSV** | Structured data | Creates searchable rows |
| **JSON** | API docs, structured | Maintains hierarchy |

### Document Processing Options

<AccordionGroup>
  <Accordion title="Chunking Strategy">
    How documents are split for search:
    - **Paragraph**: Best for structured documents
    - **Sentence**: Best for FAQs
    - **Token-based**: Best for long documents
  </Accordion>
  
  <Accordion title="Embedding Model">
    How text is converted to vectors:
    - **OpenAI ada-002**: High quality, standard
    - **Cohere**: Good for multilingual
    - **Local**: Privacy-focused
  </Accordion>
  
  <Accordion title="Overlap">
    How much context is shared between chunks:
    - Higher overlap = better context preservation
    - Lower overlap = faster search
  </Accordion>
</AccordionGroup>

## QA Pair Training

### When to Use QA Pairs

<CardGroup cols={2}>
  <Card title="✅ Great For" icon="check">
    - Brand-specific terminology
    - Exact pricing/policies
    - Consistent answers to common questions
    - Company voice and tone
  </Card>
  <Card title="⚠️ Less Effective For" icon="triangle-exclamation">

    - Complex reasoning
    - Large knowledge bases
    - Frequently changing info

### QA Pair Best Practices

<AccordionGroup>
  <Accordion title="Write Natural Questions">
    Use questions as real users would ask them:
    - ❌ "Provide information about shipping policies"
    - ✅ "How long does shipping take?"
  </Accordion>
  
  <Accordion title="Include Variations">
    Add multiple phrasings for the same question:
    - "What's the warranty?"
    - "How long is my product covered?"
    - "Is this under warranty?"
  </Accordion>
  
  <Accordion title="Complete Answers">
    Provide full, helpful answers:
    - Include all relevant details
    - Add next steps or links
    - Use your brand voice
  </Accordion>
</AccordionGroup>

## Fine-Tuning

### What is Fine-Tuning?

Fine-tuning trains the model's neural network weights with your data, creating a specialized version of the base model.

```
┌─────────────────────────────────────────────────────────┐
│                    FINE-TUNING PROCESS                   │
├─────────────────────────────────────────────────────────┤
│                                                         │
│   Base Model (GPT-4o-mini)                             │
│        │                                                │
│        ▼                                                │
│   ┌──────────────────────┐                             │
│   │  Your Training Data  │                             │
│   │  - QA pairs          │                             │
│   │  - Conversations     │                             │
│   │  - Examples          │                             │
│   └──────────────────────┘                             │
│        │                                                │
│        ▼                                                │
│   Your Custom Model                                     │
│   (Specialized behavior, your brand voice)              │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### Training Data Format

Fine-tuning uses JSONL format:

```json
{"messages": [{"role": "system", "content": "You are TechSupport AI..."}, {"role": "user", "content": "My device won't turn on"}, {"role": "assistant", "content": "I'm sorry to hear that! Let's troubleshoot together..."}]}
{"messages": [{"role": "system", "content": "You are TechSupport AI..."}, {"role": "user", "content": "How do I update firmware?"}, {"role": "assistant", "content": "Great question! Here's how to update..."}]}
```

<CardGroup cols={2}>

## Model Distillation

### What is Distillation?

Distillation transfers knowledge from a powerful model (teacher) to a smaller, faster model (student).

```
┌─────────────────────────────────────────────────────────┐
│                   MODEL DISTILLATION                     │
├─────────────────────────────────────────────────────────┤
│                                                         │
│   Teacher Model (GPT-4o)                               │
│   - Powerful but expensive                              │
│   - Generates training examples                         │
│        │                                                │
│        ▼                                                │
│   Student Model (GPT-4o-mini)                          │
│   - Learns from teacher's outputs                       │
│   - Faster and cheaper                                  │
│   - Similar quality for your use case                   │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### Benefits

| Aspect | Before Distillation | After Distillation |
|--------|---------------------|-------------------|
| **Cost** | $$$$ (GPT-4o) | $$ (fine-tuned mini) |
| **Speed** | ~3s per response | ~1s per response |
| **Quality** | Excellent | Very Good (for your domain) |

## Evaluating Training Results

### Testing Your Trained Expert

<Steps>
  <Step title="Create Test Set">
    Prepare 10-20 questions your expert should answer well
  </Step>
  <Step title="Run Tests">
    Ask each question and record the response
  </Step>
  <Step title="Evaluate">
    Score responses for accuracy, tone, and completeness
  </Step>
  <Step title="Iterate">
    Add more training data where gaps exist
  </Step>
</Steps>

### Evaluation Criteria

| Criterion | What to Check |
|-----------|---------------|
| **Accuracy** | Is the information correct? |
| **Completeness** | Is the answer thorough? |
| **Tone** | Does it match your brand voice? |
| **Relevance** | Does it answer the actual question? |
| **Helpfulness** | Would a real user be satisfied? |
